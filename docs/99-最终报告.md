## 一、核心结论

### 1.1 词典释义查询完全在本机完成

这是整个逆向过程中最关键的判断。证据链：

1. **清单层面**：`libhdmdblib.so` / `libhdlex.so` 导出了完整的词典检索 C API
   （`hdgz_search`、`hdgz_get_uwid_by_key`、`hdgz_load_dict` …）；
2. **资源层面**：全部词库以 `assets/ciku/oxford_necdict.*.adgz` 打包在 APK 内，
   合计压缩 175 MB、解压 706 MB；
3. **Java 层面**：`HaidiiAppLexiconApi` 只负责「解压 / 校验 / 下载词库」，
   真正的查询走 `LexiconSearch` → `LexiconNative.nativeSearch` → 本地 `.so`；
4. **实证层面**：逆向出的算法可以直接解出 APK 内置词库，并还原出完整的
   中英文释义、音标、例句（见 §四）。

因此：

> **「查询一个词的具体所有意思」不需要联网、不需要鉴权、不需要账号。**
> 所需的一切都在 APK 里，只是被加密打包了。

### 1.2 逆向出了「加密词库」的完整格式

`.adgz` 是一个自定义的加密压缩容器，本项目已**完整还原**其算法（§三），
并用 16 个真实词库验证通过。

### 1.3 「所有词典相关的接口」已全部定位

共 **5 层**、**13 个 JNI 方法**、**40+ 个 C 导出函数**、**11 个 Java 门面类**
（详见 `docs/02-词典接口全景清单.md`）。

## 三、还原出的算法（核心成果）

### 3.1 `.adgz` 解密

**文件头（13 字节）**

```
[0]      magic ∈ {0xD2, 0xD3, 0xDC, 0xDD}
[1..4]   seed（大端）
[5..12]  8 字节滚动校验块
[13..]   密文载荷
```

**seed 推导**（`loadAdgz` @ 0xc3ec）

```
mask = (file[8]<<24) | (file[10]<<16) | (file[7]<<8) | file[11]
seed = BE_uint32(file[1..4]) ^ mask
```

**密钥流**（`decompressAdgzTyped` @ 0xc560，常量表 @ 0x47F40）

```
ks[i] = (v10 + (ks[i-1] & 0xFFFF) * v11) % (v8 + i)      # 存低 8 位
ks[-1] = seed & 0xFFFF
```

| type | v12（周期） | v8 | v10 | v11 |
|---|---|---|---|---|
| **0（实际使用）** | **8952** | **24727** | **16432** | **23686** |
| 1 | 7416 | 91825 | 24727 | 31575 |
| 2 | 22852 | 51719 | 51719 | 23875 |

**解密后是标准 gzip 流** → `gzip.decompress()` 即得明文。

**完整性校验**（与密钥流无关，可独立验证头部划分是否正确）

```
∀ r ∈ [0,8):  XOR(所有位置 ≡ r (mod 8) 的密文字节) == file[5 + r]
```

### 3.2 HDB 索引与记录

```
[0:4]              u32 BE   索引条目数 N
[4 + 5*i]          u8      key 长度
[5 + 5*i : 9+5*i]  u32 BE  key 偏移
[key 偏移]         keylen 字节   key 字符串
[key 偏移+keylen]  u32 BE   uwid
[+4]               JSON / 二进制记录
```

- 索引项固定 5 字节，key **严格有序** → 二分查找（与原生 `sub_DB80` 完全一致）。
- 记录**无长度前缀**，由「下一条索引项的 key 偏移」界定边界。
- 词头记录的 `uwid` 就是紧跟 key 的 4 字节大端值（已与 JSON 内 `"uwid"` 字段
  交叉验证：`0x4709751B = 1191802139` ✅）。

### 3.3 三级关联模型

```
词头 key ("apple")
   │  dict.raw 二分
   ▼
词头条目 { uwid: "1191710136", dictionary: { 17001: [...], 17200: [...], ... } }
   │
   ├─ parentUwid == 词头 uwid ──► def.raw     释义条目（9 条）
   └─ parentUwid == 词头 uwid ──► example.raw 例句（16 条）
```

> **重要发现**：词头记录的 `dictionary` 字段本身就按词典版本
> （17001 牛津主词典 / 17200 朗文 / 17203 牛津用法 / 17208 现代英汉 /
> 21134 / 21135 …）聚合了该词的全部释义。
> 因此**常规查询无需扫描 126 MB 的释义库**，毫秒级返回；
> 需要逐条释义与例句时才触发全量扫描（结果落盘缓存）。

### 3.4 密钥来源

```kotlin
// com.haidii.framework.repo.lexicon.dao.a
this.c = i + 948873246;    // i = HaidiiAppEnvApi.getAtypeId() = 17001
```

→ **key = 17001 + 948873246 = 948,890,247**

## 五、Python 实现（`oxford-dict`）

### 5.1 工程

```bash
uv init --name oxford-dict --package --python 3.12 --no-workspace --vcs none
uv venv                      # .venv/ (CPython 3.12.16)
uv pip install -e .
uv add --dev pytest
```

**运行时零第三方依赖**（仅标准库：`zipfile` / `gzip` / `zlib` / `mmap` / `json` / `re`）。

### 5.2 模块

| 文件 | 职责 |
|---|---|
| `src/oxford_dict/adgz.py` | `.adgz` 解密解压（含 3 组常量表与自动探测） |
| `src/oxford_dict/hdb.py` | HDB 索引（二分查找）、记录边界、uwid 编解码 |
| `src/oxford_dict/archive.py` | APK 资产提取与明文缓存 |
| `src/oxford_dict/lexicon.py` | 词典查询 API（原生接口 1:1 映射） |
| `src/oxford_dict/cli.py` | 命令行 |

### 5.4 用法

```bash
uv run oxford-dict --extract --data work/data     # 解密词库
uv run oxford-dict apple --data work/data         # 命令行查询
uv run oxford-dict run --data work/data --json     # 结构化输出
```

```python
from oxford_dict import open_lexicon

with open_lexicon(base_dir="work/data") as lex:
    entry = lex.entry("apple")
    entry.meanings              # 全部中文释义
    entry.english_definitions   # 全部英文释义
    entry.phonetics             # 音标
    entry.load_details()        # 逐条释义条目 + 例句
```

## 六、已知限制

| 项 | 说明 |
|---|---|
| `base_swg.ui_resources.adgz` | 上帝版（`b.shangdii.cn` 渠道）资源，其 seed 推导与主版不同，本实现未覆盖；不影响任何词条查询。 |
| `.dgz` 中间格式 | 未实现（直接读 `.adgz` 明文，结果等价）。 |
| `query_split` / `click_cn_match` | 原生为 C++ 词典分词器；本实现用词库索引做最长匹配 / 前向匹配，行为接近但非逐字节等价。 |
| `hdgz_reading_*`（课文/阅读 API） | 属 `.hdb` 素材库范畴，本次未涉及。 |
| `libhdlex.so` 内部检索引擎 | 未逐函数反编译；已由「还原数据格式 + 自建索引」替代，查询能力等价且更通用。 |
| 网络接口 | 未实现鉴权还原（词典查询本就不需要联网）。 |
